# 请求模型与上游回报

请求事件表和认证文件的请求明细共用模型显示：主行是客户端请求的别名（没有别名时使用原模型），次行是 CPA 采集的上游模型名称。悬浮提示保留请求模型、CPA 转发模型和上游回报三个值。

`upstream_response_model` 仅作为独立元数据入库、归档和导出，不改变计费、Credits、预算、模型过滤及汇总统计。与 CPA 转发模型不一致时显示差异提示；别名到上游模型的正常映射不会触发误报。

旧记录和未提供原始元数据的插件显示“上游未回报”，不推测、不回填。上游回报不是对模型真实性的独立验证。

升级先备份数据库，再启动新 Keeper 执行增量迁移；热表和归档表新增一个默认空字符串的列。旧 CPA 仍可向新 Keeper 发送用量；旧 Keeper 会忽略新 CPA 的可选字段。
